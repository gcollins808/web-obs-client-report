# Architecture

Three pieces, joined by one JSON file, plus an optional fourth that carries that file over HTTPS.

```
 core web-obs            agency side                         client side
 (separate project)      capture / explore / Studio / export report app + report server
 -------------------     --------------------------------    ----------------------------------
 crawls a site      -->  _site-graph.json (a site capture)
 draws the 3D globe      Studio reviews it, builds a draft,  --> client-report.json (the one JSON file)
 (used here as a         an approver signs it off, the           opened by the viewer through a
  library, vendored)     builder exports and seals the file      private link served by apps/server
```

## 1. Core web-obs (upstream, not in this repository)

web-obs captures a site into a folder with a manifest named `_site-graph.json` (pages, links, audit findings, site
intelligence) and draws it as a 3D globe. This repository does not contain the crawler or the Obsidian plugin. It contains only
the pieces of the globe it needs, copied unchanged into `vendor/web-obs` (see `NOTICE`).

## 2. Agency side: capture, explore, Studio, export

* A capture produces `_site-graph.json`. Its shape is the `SiteGraphManifest` type in `vendor/web-obs/types/site.ts`.
* `packages/contract` turns a capture into a plain-language walkthrough (`draft.ts`, `core.ts`, `plain.ts`), checks it
  (`validate`), and builds the client report (`package.ts`: `buildClientReport`, `sealReport`, `validateClientReport`). The report
  has a strict allowlist of fields (`contract.ts`); anything private (notes, local paths, raw links) is refused, and a seal
  (SHA-256 over the content) detects later edits. The agency-only explore pack is a separate file that is never uploaded.
* `apps/viewer` is the Studio (review, checks, export, publish, captures and links tabs) and, from the same bundle, the
  client viewer. The Studio talks to a local publish helper (`apps/server/scripts/publish-helper.mjs`, 127.0.0.1 only, start
  token) to publish or archive.
* `apps/server/scripts` holds the command line side: export, publish (ssh, local folder or https), remove-capture.

## 3. Client report app and report server

* `apps/viewer` builds to one self-contained `dist-report/report.html`. It imports the vendored globe component as a library
  (`GlobeStage.tsx`) and the contract from `packages/contract`.
* `apps/server` is a small Node server without a framework. It serves the viewer page and one report per private link. Links are
  random tokens; only their hashes are stored (the registry). Every bad link gets the same "Access denied" page. Reports and
  the registry are mounted read-only. Feedback from the client is turned into an email by the server (Resend, or an outbox file).
* `deploy/` has a Dockerfile (builds the viewer, then a plain Node image with no packages) and an example compose file for a
  tunnel network with no published ports.

## 4. Optional HTTPS ingest

`apps/server/ingest` is a separate process (the only one with write access to the reports and registry volumes) that accepts a
finished client report over HTTPS, checks it against the contract, stores it under a random name and returns the link. It is off
unless `INGEST_ENABLED=1`. Its two locks, limits and audit log are described in [INGEST-SECURITY.md](INGEST-SECURITY.md).

## Dependencies between folders

```
packages/contract  -->  vendor/web-obs/{types,data}   (type and data helpers only)
apps/viewer        -->  packages/contract, vendor/web-obs
apps/server        -->  packages/contract is bundled only in tests and the export command
                        (apps/server/ingest/contract-check.mjs is a plain copy of the field lists, kept equal by a test)
fixtures           -->  generated by fixtures/make-synthetic.mjs using packages/contract
```
